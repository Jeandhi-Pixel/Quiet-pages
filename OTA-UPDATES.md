# Quiet Spaces — OTA updates and app versions

## Status and first-time requirement

**OTA updates are not present in the first Android debug APK.** Install ONE new APK that bundles `@capgo/capacitor-updater` and this patch, then future **HTML/CSS/JS** fixes can be delivered through self-hosted update bundles. The settings/notification-safe-area changes also require that new APK.

This implementation uses **manual approval**: the app checks for updates on startup/foreground and every 30 minutes, but does **not install** until you choose Update now. It first downloads and verifies the SHA-256 checksum, then saves/locks the journal immediately before switching to the new bundle. If a new bundle fails to call `notifyAppReady`, the plugin rolls it back.

## Versioning

- Current bundled web release: **v0.2.0** (defined in `app-version.js` and `package.json`).
- Android native revision: **1** (in `native-env.js` generated by the Android build step).
- The app shows its active web version under **Settings → Reminders & exercise → About & updates**.
- PWA continues its original service-worker update mechanism. The app version is shown there too.
- Native changes (new plugin, system bar config, Android SDK) require a new APK even if the web release version is higher.

## Update hosting — no separate Capgo account

Public HTTPS files under the existing GitHub Pages site:

- `https://jeandhi-pixel.github.io/Quiet-pages/ota/latest.json` — public release manifest.
- `https://jeandhi-pixel.github.io/Quiet-pages/ota/releases/quiet-spaces-vX.Y.Z.zip` — zipped **web code only**.

The APK reads that fixed HTTPS manifest with Capacitor's native HTTP client to avoid WebView CORS restrictions. It checks strict same-origin bundle URLs, semantic version ordering, native revision and a SHA-256 ZIP checksum. No journal entries, passwords, product history or profile identifiers are uploaded or transmitted by the update checker.

**Security note:** SHA-256 protects against accidental corruption, not against a compromised GitHub account or a malicious publisher who can alter both the ZIP and manifest. Protect GitHub with MFA, review commits, and publish only tested bundles. OTA bundles are public assets, never encrypt private journal data into a bundle.

## Initial setup in the existing Windows Android Studio project

1. **Export a recent encrypted journal backup** on your phone and keep your existing PWA installed.
2. Download or pull the `feature/capacitor-android-foundation` branch, copy its root web files, the `scripts` folder, `package.json` and `capacitor.config.json` into your existing Quiet-spaces project. Preserve the existing `android/` directory.
3. Open PowerShell in that folder.

```powershell
npm.cmd install
npm.cmd run android:sync
npm.cmd run android:open
```

4. Build an APK in Android Studio using **Build → Build APK(s)**. Install the APK over the previous one if signatures match. Do not uninstall the previous version to force an update when it has irreplaceable data.
5. After installation, unlock the app. In **Settings → Reminders & exercise → About & updates**, check **v0.2.0** and tap **Check for updates**. Before an OTA bundle is published, it should say **Up to date**.

## Publishing future web-only updates

**Only after this native-enabled APK has been tested and PR #4 merged into main:**

1. Test and merge the HTML/CSS/JS changes to `main` (no native/plugin changes). Do not include private journal data.
2. Open GitHub → **Actions → Publish Quiet Spaces OTA web update → Run workflow** on the `main` branch.
3. Enter a new version such as `0.2.1` (greater than the previous published release and native baseline), and short notes.
4. The workflow packages `www/` with the official Capgo CLI, computes SHA-256, commits the ZIP and `ota/latest.json` to main, then GitHub Pages publishes them.
5. On your phone, open Quiet Spaces while online. It will offer the new version. Tap **Update now**; it saves and locks the journal before applying the bundle.

Manual publishing requires a GitHub Actions workflow with **Contents: write** permission. If your repository limits workflow writes, grant the workflow permission in repository settings. If your GitHub Pages configuration is not publishing the repository `main` branch's root files, update the release hosting URL/workflow accordingly before enabling OTA.

## Rollback and data safety

The Capgo updater automatically rolls back code if the new bundle fails to become ready within its configured timeout (30 seconds). This protects the app startup but **is not a substitute for encrypted journal backups**. Updates must preserve the existing IndexedDB origin and encryption format. Keep a recent backup and retain the prior ZIP/manifest for manual rollback if needed.

Do not distribute repeated debug APKs from different signing keys as updates. For ongoing native APK releases, use a stable signed release keystore stored outside GitHub.
